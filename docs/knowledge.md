# 知見の蓄積と運用ルール

レビューのセッションで分かったことを、呼び出し元リポの専用ブランチ（既定: `amon-reviewer-knowledge`）に知見として貯め、次回以降のレビューで使います。

## 仕組み

| タイミング | すること |
| --- | --- |
| PR の作成・更新 | レビュー後に同じセッションを再開して要約を作り、`pending/<PR番号>.md` に保存する（同じPRは上書き） |
| PR のマージ | `pending/<PR番号>.md` を `knowledge/<PR番号>.md` に移す（採用） |
| マージせずに閉じる | `pending/<PR番号>.md` を削除する（破棄） |
| 次のレビュー | `knowledge/` を取り出し、置き場所だけをセッションに伝える。読むかどうかはセッションに任せる |

- 要約に何を残すかはセッションに任せます。残すものがなければ保存しません
- 要約に失敗しても、レビューとコメントは失敗扱いにしません
- 複数のPRが同時に書き込んだときは、取り込み直して自動で再試行します

## ブランチの構成

```
amon-reviewer-knowledge   # main と履歴を共有しない独立したブランチ
├─ pending/<PR番号>.md     # レビュー済み・未マージの知見
└─ knowledge/<PR番号>.md   # マージされたPRの知見（次回以降のレビューで使う）
```

知見ブランチにはデータ（Markdown）だけを置きます。レビューの仕組み（amon-reviewer のコード）は amon-reviewer リポの main にあり、知見ブランチへのマージは不要です。

## 導入時の設定

1. workflow のトリガーに `closed` を含める（マージ時の採用・破棄に使う）
2. workflow の権限を `contents: write` にする（知見ブランチへの push に使う）
3. `contents: write` はブランチ単位で絞れないため、**main にはブランチ保護をかける**
4. 閉じたPRではマージ用の参照が消えていることがあるため、`closed` のときは既定ブランチを checkout する

[`examples/workflow.yml`](../examples/workflow.yml) はこの設定済みです。知見を貯めない場合は、入力 `knowledge_branch` を空にします。

## 運用ルール

### やってよいこと

- **知見を人が直す・消す**：知見ブランチの `knowledge/<PR番号>.md` を直接編集・削除してかまいません。誤った知見や、コードが変わって古くなった知見は、見つけしだい消してください
- **保留の掃除**：workflow が失敗するなどして `pending/` に残ったファイルは、手で削除してかまいません

### やってはいけないこと

- **force push・リベース・履歴の書き換え**：同時に書き込まれた他のPRの知見が消えます。直すときは、通常のコミットで行ってください
- **main へのマージ**：知見ブランチは main と履歴を共有していません。main に取り込みたい知見がある場合は、内容を main 側の通常のPRで書き起こしてください
- **コードや設定を置くこと**：知見ブランチには `pending/` と `knowledge/` の Markdown だけを置きます

### 知見の見直し

- 知見は、書かれた時点のコードを前提にしています。大きな改修やリファクタのあとは、関係する知見に目を通してください
- 同じ内容の知見が増えてきたら、1つのファイルにまとめて残りを削除してかまいません（ファイル名は自由です。`knowledge/` 配下の `*.md` がすべて読まれます）

### 保存形式を変えるとき

amon-reviewer の改修で保存形式（ディレクトリ構成やファイルの単位）を変える場合は、次のどちらかで移行します。

1. 新しいスクリプトが古い形式も読めるようにする
2. 移行用のスクリプトを1回だけ実行し、知見ブランチの中身を新しい形式に書き換える（通常のコミットで行い、force push はしない）
