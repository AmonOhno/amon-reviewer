# React 共通UIコンポーネントのレビュー観点

React / TypeScript で作られた共通UIコンポーネントのPRをレビューしてください。
差分だけでなく、仕様書・呼び出し元・既存の類似コンポーネントなど、判断に必要なファイルは自由に読んでください。

## 必須観点

すべて確認し、該当する問題がなければ「問題なし」と書いてください。

1. **API（Props）設計**：Props は最小限か。boolean が乱立せず variant などにまとまっているか。命名や形が既存コンポーネントと揃っているか。制御／非制御の両方で正しく動くか。ref やネイティブ属性を受け渡せるか
2. **拡張性**：特定の画面・業務の都合が混ざっていないか。children・Compound Components・slot などの合成で拡張できるか。スタイルを上書きする手段があるか
3. **型と実行時の防御**：型は実行時には保証されない。`as`・`any`・`!` で型チェックをすり抜けていないか。不正値・null・外部データに備えているか。似た項目どうしで不正値の扱いが揃っているか
4. **状態とライフサイクル**：Props から導出できる値を状態に持っていないか。effect の依存配列・実行順・クリーンアップ（リスナー・タイマー・グローバルな変更）に漏れがないか。よくある配置や呼び出し方で、エラーにならず黙って失敗する経路はないか
5. **アクセシビリティ**：role / aria、ラベルとの関連付け、キーボードだけで操作できるか、フォーカス管理、コントラスト（WCAG AA）、スクリーンリーダーでの読み上げ
6. **パフォーマンス**：不要な再レンダリング、頻繁に呼ばれる処理の重さ、大量データへの備え、重い依存の追加
7. **国際化**：文言や書式（日付・数値）がハードコードされていないか
8. **仕様・ドキュメントとの整合**：仕様書・型定義・ドキュメントと実装が一致しているか。破壊的変更がある場合、その明示と移行手段があるか
9. **テスト**：ユーザーから見た振る舞いを検証しているか。境界値・不正値を含むか。実装の詳細や実時間の待機に依存していないか

## 自由観点

上記以外でも、バグ・保守性・セキュリティなどの問題に気づいたら指摘してください。

## 出力

日本語の Markdown で出力してください。各指摘には重大度（must / should / nit）と該当箇所（ファイル:行）を付けてください。
