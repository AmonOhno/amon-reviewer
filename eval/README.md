# 精度検証ケース

観点MDやプロンプトを変えたときに、レビューの精度が上がったのか下がったのかを確かめるためのケース集です。
各ケースは「問題を仕込んだ小さなサンプルPR」と「期待される指摘」の組で、特定のアプリや製品のコードは含めません。

## ケースの構成

```
eval/<観点MDの名前>/<ケース名>/
├─ case.yml       # 概要とタグ
├─ expected.md    # 期待される指摘（正解）
├─ fixture/       # サンプルPRで追加されるファイル
└─ runs/          # scripts/eval.sh の実行結果（日時ごと）
```

- ケース名は、題材にした部品の種類（`dialog`、`option-list` など）で付けます
- 1つのケースに複数の観点の問題を含めてかまいません。`case.yml` の `tags` に、含まれる観点を書きます
- `fixture/` は Git リポジトリの main（README だけ）に追加される差分として扱われます

### tags

観点MDの必須観点と対応させます。

| tag | 観点 |
| --- | --- |
| `api` | API（Props）設計 |
| `extensibility` | 拡張性 |
| `runtime-defense` | 型と実行時の防御 |
| `lifecycle` | 状態とライフサイクル |
| `a11y` | アクセシビリティ |
| `performance` | パフォーマンス |
| `i18n` | 国際化 |
| `spec` | 仕様・ドキュメントとの整合 |
| `test` | テスト |

## ui-react のケースと観点の対応

| 観点 | text-field | dialog | option-list | toast-notification |
| --- | --- | --- | --- | --- |
| API（Props）設計 | ✓ | | | |
| 拡張性 | ✓ | | | |
| 型と実行時の防御 | | | ✓ | ✓ |
| 状態とライフサイクル | ✓ | ✓ | ✓ | ✓ |
| アクセシビリティ | ✓ | ✓ | ✓ | ✓ |
| パフォーマンス | | | ✓ | ✓ |
| 国際化 | ✓ | | | |
| 仕様・ドキュメントとの整合 | | | | ✓ |
| テスト | ✓ | ✓ | | ✓ |

ケースが1つしかない観点（API設計、拡張性、国際化、仕様・ドキュメントとの整合）や、まだ扱っていない問題（破壊的変更など）のケースを優先して追加します。

## 実行と評価

```bash
scripts/eval.sh                 # すべてのケース
scripts/eval.sh ui-react        # ui-react のケースすべて
scripts/eval.sh ui-react/dialog # 1ケースだけ
```

結果（`runs/<日時>.md`）を `expected.md` と見比べ、ケースごとに次の2つを数えます。

- **見逃し**：期待される指摘のうち、拾えなかった件数
- **ノイズ**：期待される指摘にも当てはまらず、妥当でもない指摘の件数（期待される指摘にない妥当な指摘は、ノイズに数えず `expected.md` への追加を検討します）

モデルの出力は毎回ばらつくため、比べるときは同じ条件で数回ずつ実行してください。

## アプリ固有のケース

`eval/` には、どのアプリでも使える汎用的なケースだけを置きます。
アプリ固有のケースは、各アプリのリポの `.amon-reviewer/eval/` に置いてください。
