# 一般的なレビュー観点（amon-reviewer ベースライン）

すべてのリポジトリに共通して適用する観点です。リポジトリ固有のプロファイルがある場合は、
そちらの「レビュー重点」「意図的なパターン」「規約」を優先し、この一般観点は補完として使います。

## 1. 正しさ（correctness）
- 仕様・PR の説明と実装が一致しているか。境界値、空/null/undefined、オフバイワン、型変換、タイムゾーン、浮動小数点
- 分岐の取りこぼし、例外経路での状態不整合、早期 return による後処理漏れ
- 非同期処理：await 漏れ、競合状態、デッドロック、リトライの冪等性、トランザクション境界
- 既存の呼び出し元を壊していないか（シグネチャ変更、戻り値の意味変更、デフォルト値変更）

## 2. セキュリティ（security）
- 入力検証とエスケープ：SQL/NoSQL/コマンド/テンプレートインジェクション、XSS、パストラバーサル、SSRF
- 認証・認可：権限チェックの欠落、IDOR、テナント境界の越境、管理機能の露出
- 秘密情報：ハードコードされた鍵、ログや例外メッセージへの機微情報出力、クライアントへの漏洩
- 暗号・乱数・セッション・CSRF・CORS の誤設定、依存パッケージの既知脆弱性の持ち込み

## 3. データとマイグレーション（data）
- スキーマ変更の後方互換性、ロールバック可能性、大規模テーブルでのロック/長時間実行
- データ欠損・二重書き込み・整合性制約の欠落、N+1、インデックス不足

## 4. 性能・信頼性（performance / reliability）
- 計算量の悪化、ループ内 I/O、無制限のメモリ確保/ページングなしの全件取得
- タイムアウト・リトライ・サーキットブレーカ・リソース解放（接続、ファイル、ロック）
- エラーハンドリング：握りつぶし、過剰な catch、ユーザーへ返すエラーの妥当性、可観測性（ログ/メトリクス）

## 5. API・互換性（compatibility）
- 公開 API / イベント / 設定キーの破壊的変更、バージョニング、ドキュメント更新の要否

## 6. テスト（testing）
- 変更に見合うテストがあるか。正常系だけでなく異常系・境界値。テストが実装の写経になっていないか
- 不安定なテスト（時刻・乱数・順序・外部依存）の持ち込み

## 7. 保守性（maintainability）
- 既存の規約・抽象との一貫性、重複、責務の混在、過剰/不足な抽象化、読み手を誤解させる命名
- 指摘は「動作やチームに実害があるもの」に限る。好みの問題は nit として最小限に

## 重大度の基準
- critical: 本番障害・データ破損・セキュリティ事故に直結。マージ前に必ず修正
- high: 高確率でバグ/脆弱性/重大な性能劣化を起こす。原則マージ前に修正
- medium: 条件次第で問題になる、または将来の保守に明確な悪影響
- low: 改善が望ましいが急がない
- nit: 体裁・好みに近いもの
